# CPU representation comparison: implementation plan

Revised20October; replaces the prior GPU/storage implementation proposal. Goal: a small wrapper around the existing trainer, at most four new scalar fits and conditional reuse of two accepted CPU E64 fits. The coordinator authorizes an overnight CPU run; full fits follow the checks/reviews below. No new fitting has started. Exact scientific settings/metrics are in the companion specification.

## Files and interfaces

Create `experiments/representation_study/{__init__.py,protocol.py,runner.py,analysis.py}`, `configs/representation-study/cpu.json`, `notebooks/representation_comparison.ipynb`, `docs/run-representation-study.md` and focused new tests. No new storage framework, migration layer, timing-only mode or changes to frozen numerical source. protocol supplies configs/count selection; runner imports existing train/checkpoint primitives; analysis reuses independent prediction_metrics and existing model/predictor/checkpoint interfaces for BEST/LAST scoring. Numerical outputs go to fresh protected run/evidence directories, never into old fits.

## 2. Small serial runner and restart tests

Implement `run_queue(settings)`, `run_fit(config,fit_root)` and `newest_valid_checkpoint(segments,expected_identity)` as simple orchestration. Keep segment checkpoint files and existing hashed metadata format. While the child runs, retain one authenticated copy of its latest scheduled checkpoint per segment. Only state/control/BEST histories on the500-update grid are eligible. An off-grid graceful wall stop may contaminate BEST: preserve it as ineligible and fall back to the retained scheduled copy or prior segment, never merely filter JSON. If no valid save exists, report incomplete/failure rather than start over. Use a fresh numbered segment, set resume_checkpoint to the latest authenticated existing last.msgpack, and pass the fixed200000-update target to train. No new owner protocol. Fail source/config mismatch explicitly; record corrupt/unreadable candidate rejection before trying a prior segment. Only skip completed fits with complete config/provenance/checkpoint/reload evidence.

- Tests first: valid continuation, truncated newest fallback, incomplete write, wrongobjective/source refusal, future-history exclusion, duplicate boundary handling, an off-grid wall-stop that improves BEST but falls back to the retained scheduled state, completed-fit no-op and no new fit-fromzero on an identity error. Unique segment allocation must refuse concurrent folder collisions rather than overwrite.
- Existing trainer catches exceptions into summary.json: wrapper must inspect status/failure_reason, not assume a returned dictionary means success. wall_budget is incomplete; do not silently present it as a full-budget result. Preserve checkpoint evidence and resume on the next explicit queue invocation. Do not hide a numerical failure behind automatic retry.
