## Material finding CAPACITY-ENG-P2-001: enforce the child attempt at the public child entry

Specification lines21/35 require one child attempt per case and no retries. Plan Task2 lines40–45 currently defines a strict public `--probe` route and child binding tests, but does not specify a durable reservation, a one-time child entry claim, or a repeated/concurrent public-probe rejection test. A strict config/root/endpoint check alone does not consume the child allowance: the same valid saved case can satisfy those checks repeatedly and initialize/predict again. A parent-side counter does not protect the independently callable child entry.

Amend Task2 to reserve a child attempt exclusively before launching, bind the reservation to the exact root/case/config/source/code/input/update0-template/terminal receipt and reference identities, and have the public child claim a separate exclusive entry before numerical imports or initialization. Preserve reservation, entry and completion independently so an interrupted, timed-out or unreturned launch remains consumed and its unreceipted work stays unknown. Neither a controller failure nor a missing completion authorizes retry.

Add tests that a repeated/concurrent public child invocation, absent or forged reservation, and changed binding are rejected before initialization or predictions. Keep the existing one-attempt maximum in the frozen contract. The reviewed historical `width_rate_replacement.py` already contains the relevant pattern in `launch_probe`, `_claim_attempt`/`replacement_probe` and `probe-attempt.json`/`probe-entry.json`/`probe-completion.json`; it need not be edited. The exact public argument syntax is an implementation choice, provided entry proves and consumes the reservation.

Acceptance for this finding: save the amendment and obtain follow-up engineering plan review before code. This finding is about required execution enforcement, not a request for additional user authorization or a numerical retry.

## Controls that pass at the plan level

1. **Frozen contract and ordered case/model binding.** Task1 independently freezes the canonical config and source manifest and tests drift in rate, widths/order, scores and caps. Fixed width32 then64 plus an independently constructed model config avoids accepting a mutually consistent locally changed label. Public runner/child/report routes must reject private fixture controls.
2. **Fresh template versus saved support.** The plan takes only source arrays, record order, memberships, normalization and immutable raw baselines. It prohibits loading trained parameters/Adam state and moves initialization inside each arm cap. Child initialization and equality to saved update0 hashes bind the model/seed beyond labels. Unequal width state hashes are expected; equal zero-head raw metrics are required.
3. **Committed boundary validation.** Updates1 and3001 have both incoming scored states0/3000 and outgoing scores1/3001 in the 63-point sequence. Task2 binds the actual committed update to a discarded independent full-gradient/NumPy Adam proposal and tests nonzero incoming moments. Existing `late_rate._boundary` supports this, unlike `first_step_oracle`, which explicitly assumes update0 and is insufficient by itself at3001.
4. **Terminal child reproduction.** The endpoint requires update/count6000 and finite float64 state plus all128+16 energy/force predictions, absolute tolerance1e-10 with zero relative tolerance. Child template identity precedes terminal restoration; wrong widths/seeds/templates, nonfinite references and changed code/inputs are explicitly tested.
5. **Arm/global wall accounting.** Each arm has its own initialization, with3000s/7200s caps, global10800s and180s reserve before numerical dispatch. Case failure blocks later work. Fake-clock tests cover initialization/publication and report/evidence/marker overrun; successful numerical completion cannot override failed final closure.
6. **Partial work and saved reporting.** Returned computed counts, attempted updates, latest published receipt and independently verified persisted work are distinguished. Orphan snapshots do not advance the receipt. Unknown unreturned work remains unknown, and a failed/missing arm removes complete contrasts. Exact12000/1536000 totals describe an actually completed pair, with partial known work retained separately.
7. **Source/ancestry/code protections.** Pinned source metadata, original ordered inputs, checkpoint/history/child binding, fixed production config and code/dependency identities are all required before/after execution and in child/report. Forged locally consistent ancestry has a named test. Historical runners remain unchanged to preserve older hash-bound evidence.
8. **Closure and preservation.** Report/evidence persistence precedes cap acceptance; inventory, report bytes and an append-safe evidence prefix are bound by separate final closure. The plan retains RED/GREEN attempts, failures, raw snapshots and verified archive members. Scientific learning failure can coexist with integrity success.

## Implementation advisories, not additional plan blockers

- **Inspect values as well as serialized schemas.** Historical `serialized_state_metadata` validates opaque typed-byte shape/count/hash metadata; by itself it does not establish finite leaves, nonnegative Adam variance or exactly zero initial moments/readout. New `audit_state` must enforce those spec requirements when decoding saved state, without initializing a model. It may decode arrays; the saved-only restriction is on numerical model work, not reading numerical bytes.
- **Avoid schema inference by replacing dimensions.** The historical `expected_state_blueprint` changes every dimension equal to16, which is an architecture-specific heuristic. Bind each new width's state schema to its saved fresh0 template and the child's independently initialized template, as planned. Do not blindly substitute32→64 in historical tensor shapes.
- **Preserve directory ownership and scope.** Reject symlinks in every path component, not only the leaf. Prefer the existing `DirectoryLease`/anchored-write pattern for root/case ownership and durable exclusive claims; add an ownership-loss test if that pattern is reused. Root reuse rejection must not overwrite old evidence or write failure markers into a root this invocation did not create.
- **Keep closure reconstruction byte-stable.** Task3's later saved-only rebuild must verify the final closure and retain the already bound report bytes when reconstruction is identical. If substantive report/figure bytes change after closure, preserve old files and issue a separately identified correction with new hashes; do not silently invalidate the original marker. Define whether figures are written inside the substantive reporting cap or explicitly classified as later presentation artifacts.
- **Retain complete known work on later failure.** A child completion receipt remains known work even if a subsequent cap, ownership or evidence write fails. Do not replace valid child counts with zero merely because overall execution is invalid. Sum only known categories and expose an unknown-total flag/reason rather than reporting unknown work as exact zero.
