## Required repairs

### E1: Define instrumented per-microbatch execution without modifying frozen helpers

The plan requires saved work counters after each completed microbatch and budget checks throughout the numerical execution, while naming the existing `split_gradients`, `accumulated_weighted_loss_and_grad` and `verify_directional_derivatives` helpers as the implementation path. These helpers do not provide the needed observability. `gradient_diagnostics.split_gradients` checks the budget before each separate E/F batch, but calls the whole unweighted joint accumulation without a per-batch budget or completion callback. `coverage_runs.accumulated_loss_and_grad` and `loss_balance.accumulated_weighted_loss_and_grad` have neither hook. The FD helper checks the budget before evaluations but only exposes progress after a complete central-difference step, so a failure halfway through an evaluation loses exact completed-microbatch work unless an additional instrumented path exists.

Specify a script-local orchestration adapter using the frozen objective/gradient kernels, or another concrete approach that maintains the existing accumulation arithmetic while adding checks and completion receipts. Check budget before every numerical microbatch; block until its result is ready; validate it; journal actual completed calls/exposures before proceeding. Keep an attempted or in-flight marker for exceptions/operational termination, with unknown work explicitly named. Do not infer completion from a pre-call `check_budget` callback. Do not edit the frozen `src/` helpers to add hooks. Retain meaningful injected tests for a failure in the middle of unweighted joint, fixed-weight joint and each sign of an FD evaluation, including the final microbatch.

The design should freeze precise work definitions: eight E-gradient, eight F-gradient, eight unweighted-joint-gradient and eight fixed-weight-joint-gradient microbatches per complete case; eight perturbed objective evaluations per case (two objectives, two step sizes, plus/minus), each traversing eight microbatches and evaluating both objective outputs. This is 512 gradient structure exposures and 1024 perturbed-evaluation structure exposures per case, separately from 144 role-prediction entries. Objective output counts must not be conflated with evaluated structure counts or training exposure.

### E2: Resolve cap and reserve semantics

The plan says an `1800 s cap / 60 s reserve`; the design says a `1800 s` wall cap **plus** a `60 s` output reserve. These imply different numerical stop thresholds. Define one rule in both documents and the future config, for example a total 1800 s internal wall cap with the last 60 s reserved for failure/summary output, and a separate 1860 s operational kill timeout. State the budget start boundary, including whether pure guards, imports and compilation count, and keep later saved-only closure outside that cap. The once-only launcher must retain an exclusive attempt before numerical imports, record timed-out partial output and block downstream cases without a numerical retry.

## Required implementation details already compatible with the plan

- The existing pure `capacity_contract.audit_state` checks the exact checkpoint SHA, envelope/payload provenance, update and normalization, float64/finite parameters and moments, Adam count, zero-state width schema and stored parameter/optimizer hashes. Apply it to each selected historical receipt, not the terminal `commit.json` receipt reused for other updates. Bind the historical row/checkpoint identity to the pinned history prefix and selected state. `_read_checkpoint` plus `serialization.msgpack_restore(envelope['payload'])` can then restore arrays without a template initializer. Parameter dictionaries are sufficient for `model.apply`; never pass the restored optimizer dictionary into a trainer.
- Complete source guarding must check the exact manifest key set against the 343-member source inventory, complete existing `src/`/lock participant map and runtime identity. Pin the standalone analysis script, config and review artifacts separately, and enforce their required set; a supplied-only map would not detect omissions. Existing pure canonical capacity report reconstruction is available without JAX imports. Recheck original source/report/pins after analysis and again during saved-only closure.
- The model head bias adds once per atom before segment summation. The analytic scaled E-loss bias derivative therefore includes each structure's atom count: `2 * mean(n_atoms * energy_error) / energy_loss_scale_eV**2`. For fixed-composition aspirin this reduces to `2 * n_atoms * mean(error) / scale**2`. The F derivative of that position-independent bias is structurally zero. A witness test must include this factor and nonunit fixed weights.
- `gradient_geometry` emits raw-joint slopes for the gradients it receives. With weighted split gradients its slope fields describe weighted component objectives along the negative weighted joint direction. Label them accordingly; do not imply those slopes describe the unweighted components or the actual historical Adam proposal. Named reasons must accompany undefined zero-norm ratios/cosines.
- Define report gating explicitly: per-case residual/gradient interpretation requires that case's checks plus run-wide source integrity; paired pre/peak/recovery contrasts require every participating case verified. A later failure may preserve completed-case raw observations, but missing or invalid cases cannot be promoted by observation-file existence. A global source-integrity failure invalidates scientific endorsement of all affected cases.
- Preserve immutable source arrays and optimizer/count/RNG/normalization state; audit decoded state before and after, including non-parameter fields. The post-analysis hash check must occur on both successful and failed paths when a decoded state exists, not only after a successful derivative check.
