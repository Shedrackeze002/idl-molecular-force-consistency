## Why the plan passes

1. **Numerical interfaces and independent checks.** Task1 explicitly isolates projection, production update, oracle and restoration, with call/retain callbacks. It accumulates weighted raw gradients at one unchanged incoming state, weights chunks by support rather than centering chunks, checks the unmasked bias derivative before masking, preserves zero bias moments and advances the shared Adam count. Unequal chunks and deliberately different residual means make the real-model and scalar fixtures sensitive to the main incorrect implementation. The independent full128 centered objective and NumPy Adam at outgoing1/3001 verify both zero and nonzero incoming moment regimes. The actual production proposal is accepted once; reference proposals and warmup are discarded and counted separately.

2. **Restoration and source identity.** Design lines7–15 and Task2 distinguish original shared unprojected0 from projected intervention0 and retain original raw baselines. Original source state/hash/blueprint checks precede decoding; known Optax tuple reconstruction avoids parameter initialization. Exact source/code/runtime/input/launch identities are required before numerics, at closure and in saved reporting. The original frozen gate object must survive closure comparison, preventing a replacement artifact manifest from silently authorizing changed bytes.

3. **Publication and exclusivity.** Task2 reserves an exclusive ordinal1 root, requires immutable checkpoints/history/predictions and publishes a receipt last. Its child is separately token-bound and exclusive, binds configuration/provenance/source/state/history/input/gate/directory identity and performs endpoint reproduction without initialization or a new proposal. Duplicate roots/probes, substitution, provenance mismatch and last-published commits have planned real-file tests. Existing DirectoryLease/no_symlinks/safe-path helpers provide a usable ownership boundary without modifying frozen src.

4. **Work and failures.** Ready returned work, finite-valid work, unknown in-flight work, returned proposals, accepted updates and persisted checkpoints are distinct. The retained-output callback runs before finite or verification checks can discard a returned result. Partial gradients, candidate/projection vectors, states, child streams/attempt/entry/completion/work and stop reasons survive failure. Missing root completion produces a conservative saved-only report, never a retry or inferred successful execution. Source/gate drift invalidates whole-run scientific endorsement. The prior spike review's returned-microbatch, missing-summary and replacement-gate issues are covered by explicit requirements here.

5. **Caps and reporting.** The3600-second budget includes guards/imports/compile/warmup/oracles/scoring/child/primary closure and180-second reserve. The3660-second supervisor uses process-group TERM,10-second grace and KILL; the child receives actual remaining budget minus closure reserve. Late returned calls remain evidence but invalidate cap compliance. Task3 uses saved arrays only, audits score/projection receipts, preserves incomplete observations, separates matched62-postzero maxima from dense correction receipts and keeps construction-derived mean removal distinct from fresh raw scores. The raw strict10% gate remains bound to original unprojected0 on both fitted roles.

## Concrete implementation-review checks

These are implementation acceptance checks for requirements already present in the plan, not additional scientific interventions or material plan amendments:

Use the return receipt or explicit retained-artifact handle to satisfy the declared `actual_gradient` interface; the oracle independently constructs only its reference gradient/proposal. Preserve/bind sampler RNG, model RNG and normalization fields, not only params/optimizer hashes.
- Every projection receipt must bind update/kind, ordered fitting support and atom counts, raw vector artifact/hash, incoming/proposal/outgoing identities and bias delta. Initial, warmup and reference projections must remain distinguishable from accepted6001 calibrations. At scored updates, cross-check the receipt's projected identity against the checkpoint/history/prediction receipt.
