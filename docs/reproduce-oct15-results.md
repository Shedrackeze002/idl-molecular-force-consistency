# Reproducing the published results

The shared model/trainer code and the three new test modules are included. Use the existing locked environment and ordinary pytest command. The published model/trainer files are byte-identical to the reviewed implementation; the existing endpoint warning and test-discovery metadata are preserved. No dependency-lock change is made. See the export manifest for original source/config/evidence fingerprints.

Historical runs bind their original revision and full source inventory. Publication has different provenance. Do not load old checkpoints as if they were trained at the publication HEAD or bypass provenance checks. Obtain the original immutable run/source package before exact historical checkpoint reproduction. New training needs its own reviewed fixed launch record; this publication authorizes none.

The compact evidence includes MACE per-record predictions and E3x raw loss/validation histories and checkpoint reference receipts. Verify each file's published SHA-256 against reports/evidence/2026-10-15/export-manifest.json. Each manifest entry also gives the original SHA and explicitly identifies path-only transformations. Arrays are byte-identical. Numeric fields/IDs/metric definitions are unchanged; machine paths and private review-location maps are removed or normalized. The complete original packages remain retained separately.

MACE arithmetic reproduction additionally requires the frozen training/validation labels and membership sidecars from the recorded export. Verify their hashes against mace-runA/report.json, align by recordID, then recompute component MAE/RMSE and each connection's component MAE before averaging connections equally. Both original independent result reviews checked all rows with separate reductions and strict log comparison. Do not substitute test labels or unrelated published benchmark splits. The final checkpoint is primary even where the selected checkpoint scores slightly better.

For E3x, independently sum the saved validation per-group absolute errors/counts and average group MAEs equally; compare with pooled sums separately. The minimum across updates 0, 100, ..., 1000 is update 0 for both arms. The saved checkpoint receipts cover LAST at update 1000 and BEST at update 0. Full per-record validation prediction arrays are unavailable for these fits; this export supports group-reduction checking, not an independent full-array model rescore. Stored force references use flattened atoms (84,3), not (4,21,3).

Large model checkpoints, raw datasets, original notebook/runtime packages and complete journals are not supplied by this clone. Ask the project coordinator for the exact hash-listed archive, and have Idris verify each member's access before claiming reproduction readiness. Existing historical large reports still use Git LFS; their pointers/attributes are unchanged. This update adds no new LFS objects. No new models were trained to prepare this publication.
