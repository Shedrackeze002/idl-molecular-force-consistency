# Optimizer comparison (Section 5.4)

These files support Table 5 and the 13/minus analysis in Section 5.4 of the final report. `geom.py` holds the symmetry-aware RMSD matcher and connectivity check, `run_opt2.py` runs ASE L-BFGS and BFGS on the MACE Run A checkpoint from the ten original starts, and `mace_lbfgs_bfgs_results.jsonl` holds one row per run and threshold (its first line is a library warning that was captured with the output). `custom_and_hessian.py`, `path_check.py` and `hess.log` cover the finite-difference Hessian and reference-path check at the 13/minus endpoint, and `start_forces.py` gives the per-start MACE force errors quoted in Section 5.1.

The E3x runs, the MACE known-minimum runs and all FIRE runs were made on a Mac CPU with `e3x_lbfgs.py` and `e3x_fire.py`, and their outputs are in `e3x-lbfgs-2026-11-26/` and `e3x-fire-2026-11-26/`. In each folder `SUMMARY.md` and `TABLE.md` give the counts quoted in Section 5.4, `summary.json` holds the same counts in machine-readable form, `e3x/rows.jsonl` holds one row per run and stopping threshold for the seven E3x checkpoints and each checkpoint folder's `parity.json` records its loader parity check, `mace-runA-validation/` holds the MACE rows, its parity check and (in the L-BFGS folder) `cloud-comparison.json`, which shows that this MACE L-BFGS run reproduces the 7 of 10 and 9 of 10 recoveries in `mace_lbfgs_bfgs_results.jsonl`, and `diagnostics/` holds the drift, energy and curvature checks. The per-start JSON files written during the runs repeat the rows in `rows.jsonl`, so they are left out. Machine paths in the records were normalized for publication, with `$PROJECT_ROOT` for the project folder, `$RUNS_ROOT` for the folder that holds the saved training runs, `$ADMISSION_ROOT` for the MACE admission workspace and `/private/tmp/group9-optimizer-run` for the temporary run folder, and the MACE scripts here read the checkpoint by its path relative to the project folder. The run notes were edited only for wording, no number was changed, and `e3x_lbfgs.py` and `e3x_fire.py` still match the `script_sha256` values recorded in each `environment.json`. `failed-attempt-01-mace-preloaded-module/` keeps a first L-BFGS launch that the MACE loader refused at its admission check because the model modules were already loaded in the process, so it stopped before any run and holds no results. The test connections were never read in any of these runs.
